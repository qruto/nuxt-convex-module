`usePaginatedQuery` turns a paginated Convex query into a growing list — ideal for infinite scroll — while keeping every loaded page live.

```ts
const { results, status, isLoading, loadMore } = usePaginatedQuery(
  api.messages.list,
  {},
  { initialNumItems: 20 },
)
```

Add a task or toggle one and watch it update with zero round-trip latency:

::playground-tasks
::

```vue [components/TaskList.vue]
<script setup lang="ts">
import type { Id } from '#convex/dataModel'
import { api } from '#convex/api'
import { insertAtTop, optimisticallyUpdateValueInPaginatedQuery } from 'nuxt-convex-module/client'

const { results, status, isLoading, loadMore } = usePaginatedQuery(
  api.tasks.listPaginated,
  {},
  { initialNumItems: 5 },
)

const addTask = useMutation(api.tasks.add).withOptimisticUpdate(
  (localStore, args) => {
    insertAtTop({
      paginatedQuery: api.tasks.listPaginated,
      localQueryStore: localStore,
      item: {
        _id: crypto.randomUUID() as Id<'tasks'>,
        _creationTime: Date.now(),
        text: args.text,
        completed: false,
      },
    })
  },
)

const toggleTask = useMutation(api.tasks.toggle).withOptimisticUpdate(
  (localStore, args) => {
    optimisticallyUpdateValueInPaginatedQuery(
      localStore,
      api.tasks.listPaginated,
      {},
      task => task._id === args.id ? { ...task, completed: !task.completed } : task,
    )
  },
)
</script>

<template>
  <label v-for="task in results" :key="task._id">
    <input type="checkbox" :checked="task.completed" @change="toggleTask({ id: task._id })">
    {{ task.text }}
  </label>
  <button :disabled="status !== 'CanLoadMore'" @click="loadMore(5)">
    Load more
  </button>
</template>
```

## Statuses

`status` walks through four values: `LoadingFirstPage` while the initial page streams in, then `CanLoadMore` when a `loadMore(n)` call would fetch another page, `LoadingMore` while that fetch is in flight, and finally `Exhausted` once the query has no more rows. `isLoading` is a shorthand for the two loading states.

`results`, `status`, and `isLoading` are `ComputedRef`s — destructure them once and they stay reactive (use `.value` in script, bare in templates) — while `loadMore` is a stable function you can call from anywhere. Like `useQuery`, reading any of the fields throws the query error to the nearest `errorCaptured` boundary.

## Optimistic updates over pages

Updating a paginated query by hand means finding the right page. Four helpers (same names and shapes as `convex/react`, importable from `nuxt-convex-module/client`) do it for you:

| Helper | What it does |
| --- | --- |
| `insertAtTop({ paginatedQuery, argsToMatch?, localQueryStore, item })` | Prepends `item` to the first page. No-op until the first page has loaded. |
| `insertAtBottomIfLoaded({ paginatedQuery, argsToMatch?, localQueryStore, item })` | Appends `item` to the final page — only if the last page has loaded. |
| `insertAtPosition({ paginatedQuery, argsToMatch?, sortOrder, sortKeyFromItem, localQueryStore, item })` | Inserts `item` at its sorted position across the loaded pages. |
| `optimisticallyUpdateValueInPaginatedQuery(localStore, query, args, updateValue)` | Maps `updateValue` over every loaded item of the paginated query matching `args`. |

For a chat UI backed by `usePaginatedQuery(api.messages.list, ...)`, show the sent message instantly:

```ts
import { insertAtTop } from 'nuxt-convex-module/client'
import { api } from '#convex/api'
import type { Id } from '#convex/dataModel'

const sendMessage = useMutation(api.messages.send).withOptimisticUpdate(
  (localStore, args) => {
    insertAtTop({
      paginatedQuery: api.messages.list,
      argsToMatch: { channel: args.channel },
      localQueryStore: localStore,
      item: {
        _id: crypto.randomUUID() as Id<'messages'>,
        _creationTime: Date.now(),
        channel: args.channel,
        body: args.body,
      },
    })
  },
)

await sendMessage({ channel: '#general', body: 'hi' })
```

The temporary `_id` is replaced by the real document when the mutation's results sync.

## `usePaginatedQuery_experimental()`

A dual-overload variant: the positional form matches `usePaginatedQuery` above, while the object form takes a single (optionally reactive) options object — `{ query, args, initialNumItems, throwOnError? }` — and returns one `ComputedRef` of a lowercase-status union:

```ts
const page = usePaginatedQuery_experimental({
  query: api.messages.list,
  args: {},
  initialNumItems: 20,
})
// page.value: { data, status: 'pending' | 'success' | 'error',
//               canLoadMore, isLoading, error, loadMore }
```

On error (without `throwOnError`), `data` is an empty array — never the previously loaded pages.
