The core ships the generic Convex auth plumbing — a port of `convex/react`'s `ConvexProviderWithAuth`. It is **provider-agnostic**: it knows nothing about Clerk, Auth0, or Better Auth, and it is always available whether or not you have installed one of them.

::callout{icon="i-lucide-blocks"}
Looking for a specific provider? The adapters live in [Components](/components) — [Better Auth](/components/better-auth), [Clerk](/components/clerk), and [Auth0](/components/auth0). Each one wires itself into the plumbing on this page.
::

## `provideConvexAuth()`

`provideConvexAuth({ client, useAuth })` wires any auth provider's loading/authenticated flags and token fetcher into the Convex client.

Re-authentication has two triggers: pass `fetchAccessToken` as a `Ref` whose identity changes, or return the additive `authVersion` key (`MaybeRefOrGetter<unknown>`) — when either changes, auth state transitions back to loading and the token is fetched again. The bundled adapters rely on this (Clerk keys `authVersion` off the active org id + role).

Your `useAuth` composable returns `{ isLoading, isAuthenticated, fetchAccessToken }` plus the optional `authVersion`. `fetchAccessToken` is an async function returning the JWT (or `null`).

Under Nuxt the adapters call this for you; in a plain Vue app you call it yourself — see [Plain Vue](/guide/plain-vue#auth-wiring), which also covers `createScopedConvexAuthState` for installing auth state outside a component setup.

## `useConvexAuth()`

Read `{ isLoading, isAuthenticated, isRefreshing }` anywhere below the provider. Each field is a `ComputedRef<boolean>`, so the upstream destructuring idiom stays reactive:

```ts
const { isLoading, isAuthenticated } = useConvexAuth()
// isAuthenticated.value in script, plain `isAuthenticated` in templates
```

`isRefreshing` is `true` only while an already-authenticated session is re-fetching a token the server rejected — the socket is paused meanwhile. Routine background token rotation does not trigger it.

## State components

Four auto-imported components render their default slot by auth state:

```vue
<template>
  <Authenticated>Welcome back</Authenticated>
  <Unauthenticated>Please sign in</Unauthenticated>
  <AuthLoading>Checking…</AuthLoading>
  <AuthRefreshing>Refreshing your session…</AuthRefreshing>
</template>
```

None of them takes props — each is a default slot rendered under one condition:

| Component | Renders its slot when |
| --- | --- |
| `<Authenticated>` | `!isLoading && isAuthenticated` |
| `<Unauthenticated>` | `!isLoading && !isAuthenticated` |
| `<AuthLoading>` | `isLoading` |
| `<AuthRefreshing>` | `isAuthenticated && isRefreshing` — an authenticated session re-fetching a rejected token |

They read the same state `useConvexAuth()` exposes, so they work under any provider — or under a hand-rolled one.
