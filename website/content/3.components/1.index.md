Core Convex is always on. Everything in this section is **opt-in**: install the package and the integration wires itself up on the next dev run — no extra `modules` entries, and for Clerk, Auth0, Polar and nuxt-security no Nuxt-side configuration at all.

Each one is a port with the **same public API** as its upstream React/Next counterpart, adapted to Vue. Convex's own docs and examples translate line for line.

## Supported packages

| Package | What you get | Enable | Subpath | Upstream version |
|---|---|---|---|---|
| [Convex Auth](/components/convex-auth) — `@convex-dev/auth` | `provideConvexAuth` · `<ConvexAuthProvider>`, cookie sessions with SSR (`setupConvexAuthNuxt`), `useAuthActions`, `useAuthToken`, sign-in with a username or an email and a password, and with Google, Apple or GitHub | `@convex-dev/auth` | `/convex-auth/client`, `/convex-auth/server`, `/convex-auth/methods/*` | `2.0.0` |
| [Better Auth](/components/better-auth) — `@convex-dev/better-auth` | `useBetterAuth`, `/api/auth/**` proxy, SSR prefetch, `convex-auth` middleware, `<AuthBoundary>`, `convexBetterAuthNuxt` | `@convex-dev/better-auth` + `better-auth` | `/better-auth/client`, `/better-auth/server` | `0.13.0` |
| [Clerk](/components/clerk) — `convex/react-clerk` | `provideConvexWithClerk` · `<ConvexProviderWithClerk>` | `@clerk/vue` | `/clerk/client` | `1.50.0` |
| [Auth0](/components/auth0) — `convex/react-auth0` | `provideConvexWithAuth0` · `<ConvexProviderWithAuth0>` | `@auth0/auth0-vue` | `/auth0/client` | `1.50.0` |
| [Polar](/components/polar) — `@convex-dev/polar` | Billing — `<CheckoutLink>` · `<CustomerPortalLink>` | `@convex-dev/polar` + `@polar-sh/checkout` | `/polar/client` | `0.9.2` |
| [Text Streaming](/components/persistent-text-streaming) — `@convex-dev/persistent-text-streaming` | `useStream`: stream text over HTTP, stored in Convex | `@convex-dev/persistent-text-streaming` | `/persistent-text-streaming/client` | `0.3.5` |
| [Presence](/components/presence) — `@convex-dev/presence` | `usePresence` · `<FacePile>`: who is in a room, live | `@convex-dev/presence` | `/presence/client`, `/presence/facepile` | `0.4.0` |
| [R2](/components/r2) — `@convex-dev/r2` | `useUploadFile`: upload to Cloudflare R2 with progress | `@convex-dev/r2` | `/r2/client` | `0.10.4` |
| [Rate Limiter](/components/rate-limiter) — `@convex-dev/rate-limiter` | `useRateLimit`: whether an action is allowed now, and when to retry | `@convex-dev/rate-limiter` | `/rate-limiter/client` | `0.4.3` |
| [nuxt-security](/getting-started/security) | A Convex-aware CSP and security headers | `nuxt-security` | — | — |

Subpaths are `nuxt-convex-module/<subpath>`, see [subpath exports](/api-reference#subpath-exports). `/clerk/client`, `/auth0/client`, `/polar/client` and the components' own subpaths are self-contained, so they also work in a [plain Vue](/guide/plain-vue) app; `/better-auth/client` and `/better-auth/server` rely on Nuxt-provided aliases and runtime config. Auto-detection reads your `package.json`: an integration switches on when its package is a dependency of your app.

The authoritative file-by-file map and pinned upstream baselines live in [`PARITY.md`](https://github.com/qruto/nuxt-convex-module/blob/main/PARITY.md).

## Installing

You only ever add **one** module. Install the package you want and it lights up:

**Better Auth**

:pm-install{packages="@convex-dev/better-auth@~0.13.0 better-auth@~1.7.16"}

**Clerk**

:pm-install{packages="@clerk/vue"}

**Auth0**

:pm-install{packages="@auth0/auth0-vue"}

**Polar billing**

:pm-install{packages="@convex-dev/polar@~0.9.0 @polar-sh/checkout@~0.6.0"}

**Text streaming**

:pm-install{packages="@convex-dev/persistent-text-streaming@~0.3.0"}

**Presence**

:pm-install{packages="@convex-dev/presence@~0.4.0"}

**R2 uploads**

:pm-install{packages="@convex-dev/r2@~0.10.0"}

**Rate limits**

:pm-install{packages="@convex-dev/rate-limiter@~0.4.0"}

**Security headers**

:pm-install{packages="nuxt-security"}

Your `modules` array never grows — the integration is detected from the installed package:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-convex-module'],
})
```

Auto-detection is the default, not a requirement. Force one on or off — or point Better Auth at your own auth client — through the `convex` key:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-convex-module'],

  convex: {
    // betterAuth: false,
    // betterAuth: { authClient: './app/convex-auth-client' },
    // clerk: false,
    // auth0: false,
    // polar: false,
    // persistentTextStreaming: false,
    // presence: false,
    // r2: false,
    // rateLimiter: false,
    // security: false,
    // devScript: false,
  },
})
```

Full option reference: [configuration](/getting-started/configuration#module-options-convex).

## Using none of them

Pure Convex with no auth and no billing? Install none of these — you get just the data layer, the module provides a base client on its own, and nothing drags an auth provider or Polar into your bundle.

::callout{icon="i-lucide-server"}
**Server-only Convex components** have no client integration to port. Install them in your Convex deployment and call their functions from Vue with the ordinary `useMutation` / `useAction` composables, and watch whatever they record with [`useQuery`](/guide/queries). Browse them at [convex.dev/components](https://www.convex.dev/components).
::
