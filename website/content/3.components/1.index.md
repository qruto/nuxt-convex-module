Core Convex is always on. Everything in this section is **opt-in**: install the package and the integration wires itself up on the next dev run — no extra `modules` entries, and for Clerk, Auth0, Polar and nuxt-security no Nuxt-side configuration at all.

Each one is a port with the **same public API** as its upstream React/Next counterpart, adapted to Vue. Convex's own docs and examples translate line for line.

## Supported packages

| Package | What you get | Enable | Subpath | Upstream version |
|---|---|---|---|---|
| [Better Auth](/components/better-auth) — `@convex-dev/better-auth` | `useBetterAuth`, `/api/auth/**` proxy, SSR prefetch, `convex-auth` middleware, `<AuthBoundary>`, `convexAuth` | `@convex-dev/better-auth` + `better-auth` | `/better-auth/client`, `/better-auth/server` | `0.12.5` |
| [Clerk](/components/clerk) — `convex/react-clerk` | `provideConvexAuthFromClerk` · `<ConvexProviderWithClerk>` | `@clerk/vue` | `/clerk/client` | `1.45.0` |
| [Auth0](/components/auth0) — `convex/react-auth0` | `provideConvexAuthFromAuth0` · `<ConvexProviderWithAuth0>` | `@auth0/auth0-vue` | `/auth0/client` | `1.45.0` |
| [Polar](/components/polar) — `@convex-dev/polar` | Billing — `<CheckoutLink>` · `<CustomerPortalLink>` | `@convex-dev/polar` + `@polar-sh/checkout` | `/polar/client` | `0.9.2` |
| [nuxt-security](/getting-started/security) | A Convex-aware CSP and security headers | `nuxt-security` | — | — |

Subpaths are `nuxt-convex-module/<subpath>`; each `/client` has a `/vue` alias — the same file under a Vue-flavoured name, see [subpath exports](/api-reference#subpath-exports). `/clerk/client`, `/auth0/client`, and `/polar/client` are self-contained, so they also work in a [plain Vue](/guide/plain-vue) app; `/better-auth/client` and `/better-auth/server` rely on Nuxt-provided aliases and runtime config. Auto-detection reads your `package.json`: an integration switches on when its package is a dependency of your app.

The authoritative file-by-file map and pinned upstream baselines live in [`PARITY.md`](https://github.com/qruto/nuxt-convex-module/blob/main/PARITY.md).

## Installing

You only ever add **one** module. Install the package you want and it lights up:

**Better Auth**

:pm-install{packages="@convex-dev/better-auth better-auth"}

**Clerk**

:pm-install{packages="@clerk/vue"}

**Auth0**

:pm-install{packages="@auth0/auth0-vue"}

**Polar billing**

:pm-install{packages="@convex-dev/polar @polar-sh/checkout"}

**Security headers**

:pm-install{packages="nuxt-security"}

Your `modules` array never grows — the integration is detected from the installed package:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-convex-module'],
})
```

Auto-detection is the default, not a requirement. Force one on or off — or point Better Auth at your own auth client — through the `convex` key:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-convex-module'],

  convex: {
    // betterAuth: false,
    // betterAuth: { authClient: './app/convex-auth-client' },
    // clerk: false,
    // auth0: false,
    // polar: false,
    // security: false,
    // devScript: false,
    // authRoute: '/api/auth',
  },
})
```

Full option reference: [configuration](/getting-started/configuration#module-options-convex).

## Using none of them

Pure Convex with no auth and no billing? Install none of these — you get just the data layer, the module provides a base client on its own, and nothing drags an auth provider or Polar into your bundle.

::callout{icon="i-lucide-server"}
**Server-only Convex components** have no client integration to port. Install them in your Convex deployment and call their functions from Vue with the ordinary `useMutation` / `useAction` composables, and watch whatever they record with [`useQuery`](/guide/queries). Browse them at [convex.dev/components](https://www.convex.dev/components).
::
