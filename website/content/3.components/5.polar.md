A Vue port of `@convex-dev/polar/react`'s two billing components. [Polar](https://polar.sh) handles the checkout and the customer portal; this package ports only the framework-side links that open them.

:upstream-baseline{source="polar"}

## Install

:pm-install{packages="@convex-dev/polar@~0.9.0 @polar-sh/checkout@~0.4.0"}

The components register globally on the next dev run. Auto-registration is a Nuxt convenience — in a [plain Vue](/guide/plain-vue) app, import them from `nuxt-convex-module/polar/vue` and register them yourself.

## Configure

Convex-side setup (`convex.config.ts`, the `Polar` instance and its exported actions) is unchanged from [`@convex-dev/polar`'s guide](https://www.convex.dev/components/polar). Nothing is needed in `nuxt.config.ts` beyond `convex.polar: false` if you want to force the components off.

Both components take the Polar action references (`generateCheckoutLink`, `generateCustomerPortalUrl`) through the required `polar-api` prop, as upstream's `polarApi`: pass the module that exports them, usually `api.billing`.

## Use

::playground-billing
::

```vue
<script setup lang="ts">
import { api } from '#convex/api'
</script>

<template>
  <!-- Auto-registered, no component imports. -->
  <CheckoutLink :polar-api="api.billing" :product-ids="['demo-product']" :embed="false" target="_blank">
    Buy demo product
  </CheckoutLink>

  <CustomerPortalLink :polar-api="api.billing" return-url="/components/polar">
    Manage subscription
  </CustomerPortalLink>
</template>
```

The components above are the **real published ones**, but this site has no Polar account behind it: the Convex actions are **demo stand-ins** that implement `@convex-dev/polar`'s exact action contract and return `sandbox.polar.sh` URLs. That is also why the demo passes `:embed="false"` — the sandbox URL is not a real Polar checkout, so it must open as a plain link instead of the embedded overlay. With a real Polar setup you keep the default `embed`, and every prop below works as upstream documents.

### `<CheckoutLink>`

Renders a Polar checkout link — embedded modal (default) or redirect — with optional lazy generation and trial configuration:

```vue
<template>
  <CheckoutLink :polar-api="api.billing" :product-ids="[productId]" :trial-interval-count="7" trial-interval="day">
    Start free trial
  </CheckoutLink>
</template>
```

| Prop | Type | Default | Purpose |
| --- | --- | --- | --- |
| `polar-api` | `Pick<PolarComponentApi, 'generateCheckoutLink'>` | required | The module exporting the action, usually `api.billing` |
| `product-ids` | `string[]` | required | Products offered at checkout |
| `embed` | `boolean` | `true` | Embedded modal; set `:embed="false"` to open the Polar checkout page instead |
| `lazy` | `boolean` | `false` | Generate the checkout URL on click instead of on mount |
| `theme` | `'dark' \| 'light'` | `'dark'` | Embedded checkout theme |
| `subscription-id` | `string` | — | Upgrade/change an existing subscription |
| `metadata` | `Record<string, string>` | — | Extra checkout metadata |
| `trial-interval` | `'day' \| 'week' \| 'month' \| 'year' \| null` | — | Free-trial unit |
| `trial-interval-count` | `number \| null` | — | Free-trial length |
| `locale` | `string` | — | Checkout locale |

The rendered `<a>` merges your attributes, so a `@click` of your own fires alongside the lazy handler instead of replacing it.

### `<CustomerPortalLink>`

A link to the Polar customer portal (subscription management) — renders nothing until the portal URL resolves:

```vue
<template>
  <CustomerPortalLink :polar-api="api.billing">Manage subscription</CustomerPortalLink>
</template>
```

| Prop | Type | Default | Purpose |
| --- | --- | --- | --- |
| `polar-api` | `Pick<PolarComponentApi, 'generateCustomerPortalUrl'>` | required | The module exporting the action, usually `api.billing` |
| `return-url` | `string` | — | Forwarded to `generateCustomerPortalUrl`; the portal URL re-fetches when it changes |

The rendered anchor opens in a new tab (`target="_blank"`).
