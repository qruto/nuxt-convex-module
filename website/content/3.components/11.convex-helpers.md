[`convex-helpers`](https://github.com/get-convex/convex-helpers) is Convex's package of server and client utilities. Its server half works in any app as it is. This page covers the Vue port of its React half:

- **Sessions**: an ID per browser tab, passed to your functions, for users who have not signed in.
- **Query cache**: query subscriptions stay open for a while after a component unmounts, so going back to a page shows its data at once.
- **A `useQuery` with a status object**: `status`, `data` and `error` in one ref, without throwing.
- **Pagination for the `stream` and `paginator` server helpers.**

:upstream-baseline{source="convex-helpers"}

## Install

:pm-install{packages="convex-helpers@~0.1.135"}

The session composables, `provideConvexQueryCache` and `makeUseQueryWithStatus` are auto-imported on the next dev run.

## Sessions

Provide the session in a component above the ones that use it, usually `app.vue`:

```vue [app.vue]
<script setup lang="ts">
provideSession({ ssrFriendly: true })
</script>

<template>
  <NuxtPage />
</template>
```

Then call your functions through the session composables. Each adds `sessionId` to the arguments:

```vue [components/Cart.vue]
<script setup lang="ts">
import { api } from '~~/convex/_generated/api'

const items = useSessionQuery(api.cart.list, {})
const addItem = useSessionMutation(api.cart.add)
</script>

<template>
  <ul><li v-for="item in items" :key="item._id">{{ item.name }}</li></ul>
  <button @click="addItem({ name: 'Socks' })">Add socks</button>
</template>
```

On the Convex side, the functions take `sessionId: vSessionId` from `convex-helpers/server/sessions`, as [the helpers' guide](https://stack.convex.dev/track-sessions-without-cookies) describes.

| Option | Default | Purpose |
| --- | --- | --- |
| `ssrFriendly` | `false` | Set it in Nuxt. The server render has no session ID, so queries are skipped and calls wait until the page has mounted. |
| `useStorage` | `sessionStorage`, one ID per tab | A composable that returns a writable ref, such as VueUse's `useLocalStorage` for one ID per browser. |
| `storageKey` | `convex-session-id` | The storage key. |
| `idGenerator` | `crypto.randomUUID` | Makes a new ID. On an `http://` address other than localhost, where `crypto.randomUUID` is missing, the default builds the same format from `crypto.getRandomValues`. |

The options can be a value, a ref or a getter. A new `useStorage` or `storageKey` reads the ID from the new store.

`useSessionId()` returns `[sessionId, refreshSessionId, sessionIdPromise]`: a ref of the ID, a function that makes a new ID (for example after a sign-out), and a ref of a promise that resolves once there is one. `useSessionAction` and `useSessionPaginatedQuery` work like their core twins. `useSessionIdArg(args)` adds the ID to arguments you pass to another composable.

`<SessionProvider>` is the same as `provideSession`, as a component.

For calls outside components, such as in a Pinia store, make the app's client a session client:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-convex-module'],
  convex: { convexHelpers: { sessionClient: true } },
})
```

`useConvex()` then returns a `ConvexVueSessionClient`, whose `sessionQuery`, `sessionMutation` and `sessionAction` add the session ID. `useConvex()` is still typed as the plain client, so narrow it. Call it where Vue can inject, such as a component's setup, a plugin or a Pinia store, and hand the client to the code that needs it:

```ts
import { ConvexVueSessionClient } from 'nuxt-convex-module/convex-helpers/sessions'

const convex = useConvex()
if (convex instanceof ConvexVueSessionClient) {
  await convex.sessionMutation(api.cart.add, { name: 'Socks' })
}
```

`provideSession` keeps its ID and the client's in step: a new ID, a refreshed one, and one a newly selected store already holds.

## Query cache

Provide the cache once, in `app.vue`:

```vue [app.vue]
<script setup lang="ts">
provideConvexQueryCache({ expiration: 5 * 60 * 1000 })
</script>
```

Then import the cached composables where you want the cache. They have the same names and arguments as the core ones:

```ts
import { useQuery, usePaginatedQuery } from 'nuxt-convex-module/convex-helpers/cache'

const messages = useQuery(api.messages.list, { channel: '#general' })
```

A query keeps its subscription for `expiration` milliseconds (5 minutes by default) after the last component that uses it unmounts, and at most `maxIdleEntries` of those (250) stay open. `debug: true` logs the cache every 3 seconds in the browser. The options can be a ref or a getter; a change builds a new cache. The cached `usePaginatedQuery` takes `customPagination: true` for the `stream` and `paginator` server helpers.

## A status-object query

`useQuery` from `nuxt-convex-module/convex-helpers/client` returns a ref of `{ status, data, error, isSuccess, isPending, isError }` and never throws:

```vue
<script setup lang="ts">
import { useQuery } from 'nuxt-convex-module/convex-helpers/client'
import { api } from '~~/convex/_generated/api'

const result = useQuery(api.users.current, {})
</script>

<template>
  <p v-if="result.isPending">Loading…</p>
  <p v-else-if="result.isError">{{ result.error.message }}</p>
  <p v-else>{{ result.data.name }}</p>
</template>
```

`makeUseQueryWithStatus(useQueries)` makes the same on another `useQueries`, such as the cached one.

## Pagination for the stream helpers

The `stream` and `paginator` server helpers need pages that are joined explicitly when more load. Use `usePaginatedQuery` from `nuxt-convex-module/convex-helpers/client` for them, with the same arguments as the core one. Here the query and the options can also be a ref or a getter; a new query starts again from the first page.
