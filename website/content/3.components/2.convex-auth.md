A Vue port of `@convex-dev/auth/react` and a Nuxt port of `@convex-dev/auth/ssr/nextjs`. [Convex Auth](https://docs.convex.dev/auth/convex-auth) keeps users and sessions in your Convex deployment, so there is no separate auth service. The port binds the package's own session engine, `@convex-dev/auth/browser`, to the provider-agnostic [Convex auth state](/guide/auth-state).

:upstream-baseline{source="convex-auth" entry="@convex-dev/auth/react + ssr/nextjs"}

::note
Sign-in with a username and password is ported. Email and password, OAuth and passkeys are not ported yet.
::

## Install

:pm-install{packages="@convex-dev/auth"}

The client auto-enables on the next dev run. `@convex-dev/auth` needs `convex` 1.48 or newer.

## Configure

Set up the Convex side as [Convex Auth's guide](https://docs.convex.dev/auth/convex-auth) describes: the component in `convex.config.ts`, and an `auth.ts` that exports `refreshSession`, `signOut`, `isAuthenticated` and the functions of each sign-in method. Nothing is required in `nuxt.config.ts`. Set `convex.convexAuth: false` only to force the client off.

## Choose where the session lives

| | Browser storage | Cookies |
| --- | --- | --- |
| The refresh token | in `localStorage` | in an `httpOnly` cookie the page's scripts cannot read |
| The server | never sees the session | renders signed-in data, and your server routes know the user |
| Setup | one call in `app.vue` | one file in `server/` |

Use cookies for an app that renders on the server. The two do not mix: with the server file in place, do not call `provideConvexAuth`.

## Browser storage

Call the composable in a top-level component, above anything that reads Convex data:

```vue [app.vue]
<script setup lang="ts">
import { api } from '~~/convex/_generated/api'

// A Vue port of `<ConvexAuthProvider>`.
provideConvexAuth({
  api: {
    refreshSession: api.auth.refreshSession,
    signOut: api.auth.signOut,
    isAuthenticated: api.auth.isAuthenticated,
  },
})
</script>

<template>
  <Authenticated>Signed in</Authenticated>
  <Unauthenticated>Sign in</Unauthenticated>
</template>
```

The provider stores the session, refreshes the access token before it expires and shares the session between tabs. It also subscribes to `isAuthenticated`, so a session revoked on the server signs the browser out without waiting for the token to expire.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `api` | `ConvexAuthApi` | required | The app's `refreshSession`, `signOut` and `isAuthenticated` references. |
| `client` | `ConvexVueClient` | the injected client | Override the Convex client to authenticate. Upstream requires it. |
| `storage` | `TokenStorage` | `localStorage` | Where the tokens are kept. |
| `storageNamespace` | `string` | the deployment URL | Tokens are shared between clients with the same namespace. |
| `ambientSignIns` | `AmbientSignInClient[]` | `[oauth()]` | Advanced: sign-in methods that act on page load. |

`<ConvexAuthProvider>` is the same call as a wrapper component, with the options as props.

## Cookie sessions and server rendering

Create one file. Its default export is what switches cookie sessions on:

```ts [server/convex-auth.ts]
import { api } from '#convex/api'

export default setupConvexAuthNuxt({
  refreshSession: api.auth.refreshSession,
  signOut: api.auth.signOut,
  isAuthenticated: api.auth.isAuthenticated,
  // Every function that can start a session. Anything not listed is refused.
  signIn: [
    api.auth.signInWithUsernamePassword,
    api.auth.signUpWithUsernamePassword,
  ],
})
```

Restart `nuxt dev` after creating the file. The module then does the rest:

- It mounts `POST /api/_convex/auth/signin`, `/refresh` and `/signout`. The sign-in composables call the first one, so the refresh token goes straight into a cookie.
- It refreshes a session that is about to expire before each render and each server route.
- It starts the client for you. There is no provider to call, and `useAuthActions()` and the sign-in composables work in every component, `app.vue` included.

Signed-in data renders on the server with no extra code, because [`useAsyncQuery`](/guide/server-and-ssr) sends the session's token:

```vue [pages/index.vue]
<script setup lang="ts">
import { api } from '~~/convex/_generated/api'

const { data: user } = await useAsyncQuery(api.users.loggedInUser, {})
</script>
```

A page rendered for a signed-in visitor answers `Cache-Control: private, no-store`, because it carries that visitor's token.

In your own server routes, import the file and ask it:

```ts [server/api/me.get.ts]
import { api } from '#convex/api'
import auth from '../convex-auth'

export default defineEventHandler(async (event) => {
  if (!await auth.isAuthenticatedNuxt(event)) {
    throw createError({ status: 401 })
  }
  const token = await auth.convexAuthNuxtAccessToken(event)
  return fetchQuery(api.users.loggedInUser, {}, { token: token! })
})
```

`isAuthenticatedNuxt(event)` asks your deployment, so a forged cookie does not pass. `convexAuthNuxtAccessToken(event)` only reads the token, for calls that the deployment verifies anyway.

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `refreshSession`, `signOut`, `isAuthenticated` | function references | required | The app's functions from `convex/auth.ts`. |
| `signIn` | function references | required | The functions the sign-in route may call. |
| `convexUrl` | `string` | the module's deployment URL | Override the deployment the server talks to. Upstream requires it. |
| `cookieOptions` | `{ secure?, path?, domain? }` | `secure` outside `nuxt dev` | Attributes of the two auth cookies. |
| `allowedOrigins` | `string[]` | none | Extra origins the routes accept, for a proxy that rewrites `Host`. |

During a server render the auth state reads as loading, as in Next.js, so `<Authenticated>` content appears once the browser has connected. Render signed-in data through `useAsyncQuery` instead.

## Sign in with a username and password

With browser storage, use these composables in a component below the one that calls `provideConvexAuth`. With cookies, use them anywhere:

```vue [components/LogIn.vue]
<script setup lang="ts">
import { api } from '~~/convex/_generated/api'

const { signIn, pending } = useSignInWithUsernamePassword(api.auth)
const username = ref('')
const password = ref('')
const failed = ref(false)

async function onSubmit() {
  const result = await signIn({ username: username.value, password: password.value })
  failed.value = result.status !== 'complete'
}
</script>

<template>
  <form @submit.prevent="onSubmit">
    <input v-model="username" name="username" autocomplete="username" required :disabled="pending">
    <input v-model="password" name="password" type="password" autocomplete="current-password" required :disabled="pending">
    <button type="submit" :disabled="pending">Log in</button>
    <p v-if="failed">Wrong username or password.</p>
  </form>
</template>
```

`signIn` never throws. It resolves to `{ status: 'complete' }` or to `{ status: 'error', userError }`, and a network or server failure arrives as `userError.error === 'OTHER_ERROR'` with the thrown value on `cause`. `useSignUpWithUsernamePassword(api.auth)` has the same shape and returns `signUp`.

## Sign out, and the access token

```ts
const { signOut, setSession } = useAuthActions()
const token = useAuthToken()
```

`signOut` revokes the session on the server and clears it in the browser. `setSession` adopts the tokens a sign-in mutation returned, for a sign-in you run yourself. `useAuthToken()` is a ref of the current access token, or `null` when signed out. Send it as `Authorization: Bearer …` to your own Convex HTTP actions and nowhere else.
