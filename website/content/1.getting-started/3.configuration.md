## Module options (`convex`)

| Option | Type | Default | Description |
|---|---|---|---|
| `url` | `string` | `NUXT_PUBLIC_CONVEX_URL` | Convex deployment URL. |
| `siteUrl` | `string` | `NUXT_PUBLIC_CONVEX_SITE_URL` | Convex `.site` URL (HTTP actions / Better Auth endpoints). |
| `betterAuth` | `boolean \| { authClient }` | auto-detect | Force the Better Auth integration on/off, or pass `{ authClient: './path/to/module' }` to point at your own auth-client module (see [bring your own auth client](/components/better-auth#bring-your-own-auth-client)). Auto-enabled when `@convex-dev/better-auth` is installed. |
| `clerk` | `boolean` | auto-detect | Force the [Clerk](/components/clerk) adapter on/off. Auto-enabled when `@clerk/vue` is installed. |
| `auth0` | `boolean` | auto-detect | Force the [Auth0](/components/auth0) adapter on/off. Auto-enabled when `@auth0/auth0-vue` is installed. |
| `polar` | `boolean` | auto-detect | Force the [Polar](/components/polar) components on/off. Auto-enabled when `@convex-dev/polar` is installed. |
| `authRoute` | `string` | `/api/auth` | Where the same-origin Better Auth proxy mounts. |
| `devtools` | `boolean` | `true` | The [Convex tab in Nuxt DevTools](/guide/devtools) (dev only). |

## Runtime config

The module publishes:

- `runtimeConfig.public.convex.url` / `.siteUrl`
- `runtimeConfig.convex.siteUrl`

Set them via environment variables (`NUXT_PUBLIC_CONVEX_URL`, `NUXT_PUBLIC_CONVEX_SITE_URL`) or the `convex` module options. The module resolves both at **build time** (module options win over the environment), and warns if no Convex URL is found.

::note
Module options and the build-time environment are resolved into `runtimeConfig`, so the same `NUXT_PUBLIC_CONVEX_URL` / `NUXT_PUBLIC_CONVEX_SITE_URL` also override the published values at **runtime** (e.g. one container image across environments) via Nitro's native runtime-config expansion — the public keys map to `runtimeConfig.public.convex`, plus `NUXT_CONVEX_SITE_URL` for the private `runtimeConfig.convex.siteUrl`.
::

## Import aliases

The module registers ordered `#convex/*` aliases (for both Vite and Nitro) pointing at your Convex functions directory and its generated modules, so you never spell out `_generated`:

```ts
import { api } from '#convex/api'
import { query, mutation } from '#convex/server'
import type { Doc, Id } from '#convex/dataModel'
```

| Alias | Resolves to |
|---|---|
| `#convex/api` | `_generated/api` (`api`, `internal`, `components`) |
| `#convex/server` | `_generated/server` (`query`, `mutation`, `action`, …) |
| `#convex/dataModel` | `_generated/dataModel` (`DataModel`, `Doc`, `Id`, …) |
| `#convex/_generated` | `_generated` |
| `#convex` | your functions directory |

::note
Order matters: the specific generated-module aliases are registered **before** the catch-all `#convex`, because the alias resolver is first-match-wins and `#convex` is a prefix of `#convex/api`.
::

The functions directory resolves in order: the `functions` field in `convex.json` (normalized — leading `./` and trailing slashes stripped), otherwise the `convex/` default. If `convex.json` fails to parse, the module warns and falls back to the `convex/` default.

You often don't need `#convex/api` at all: a generated plugin auto-provides the `api` app-wide, so namespace-reading composables and components (`<CheckoutLink>`, …) work with zero arguments. Before `convex dev` has emitted `_generated/`, the plugin is a no-op and those features degrade gracefully.

### `#convex/auth-client`

Beyond `#convex/*`, the module registers one more alias (Vite + Nitro, always — even with Better Auth off, so type-checking resolves): it points at your `betterAuth.authClient` module when set (absolute, or relative to the project root), otherwise at the bundled Better Auth client. The Better Auth runtime (`useAuth`, `<AuthBoundary>` typing, cross-domain helpers) resolves the client through this alias — see [bring your own auth client](/components/better-auth#bring-your-own-auth-client).

## Security (CSP)

The module bundles [`nuxt-security`](https://nuxt-security.vercel.app) as a module dependency and tightens a **Convex-aware Content Security Policy**: in production builds `connect-src` allows your deployment — and, when `siteUrl` is configured, the `.site` origin — over both HTTPS and WebSocket, while `img-src` / `media-src` allow Convex-served storage. The resource directives apply in `nuxt dev` too (nuxt-security enforces its default `img-src` during dev, which would otherwise block files served from Convex storage); `connect-src` is left untouched in dev so the Vite HMR and devtools WebSockets keep working. Your own directives are preserved — the Convex origins are appended.

The defaults apply only when the Convex URL is known at **build time** (`convex.url` or `NUXT_PUBLIC_CONVEX_URL` during the build), and setting `security: false` (or `security.headers.contentSecurityPolicy: false`) opts out entirely. Configure everything else through the standard `security` key.
