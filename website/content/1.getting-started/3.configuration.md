## Module options (`convex`)

| Option | Type | Default | Description |
|---|---|---|---|
| `url` | `string` | `NUXT_PUBLIC_CONVEX_URL`, then `CONVEX_URL` | Convex deployment URL. |
| `siteUrl` | `string` | `NUXT_PUBLIC_CONVEX_SITE_URL`, then `CONVEX_SITE_URL` | Convex `.site` URL (HTTP actions / Better Auth endpoints). |
| `betterAuth` | `boolean \| BetterAuthModuleOptions` | auto-detect | Force the [Better Auth](/components/better-auth) integration on/off, or configure it with the three keys below. Auto-enabled when `@convex-dev/better-auth` is a dependency. |
| `betterAuth.authClient` | `string` | bundled client | Path to your own auth-client module, absolute or relative to the project root — see [bring your own auth client](/components/better-auth#bring-your-own-auth-client). |
| `betterAuth.crossDomainCallbackRoute` | `string` | `''` (unrestricted) | The one route allowed to exchange a cross-domain `?ott=` token — see [cross-domain one-time tokens](/getting-started/security#cross-domain-one-time-tokens). |
| `betterAuth.loginPath` | `string` | `/login` | Where the `auth` route middleware sends unauthenticated visitors. |
| `clerk` | `boolean` | auto-detect | Force the [Clerk](/components/clerk) adapter on/off. Auto-enabled when `@clerk/vue` is a dependency. |
| `auth0` | `boolean` | auto-detect | Force the [Auth0](/components/auth0) adapter on/off. Auto-enabled when `@auth0/auth0-vue` is a dependency. |
| `polar` | `boolean` | auto-detect | Force the [Polar](/components/polar) components on/off. Auto-enabled when `@convex-dev/polar` is a dependency. |
| `security` | `boolean` | auto-detect | Force the [nuxt-security](/getting-started/security) integration on/off. Auto-enabled when `nuxt-security` is a dependency or listed in `modules`. |
| `authRoute` | `string` | `/api/auth` | Where the same-origin Better Auth proxy mounts. A missing leading `/` is added with a warning; a trailing `/` is stripped. Any value other than `/api/auth` needs your own `betterAuth.authClient` created with that `basePath`, because the bundled client calls `/api/auth` — the module errors at startup otherwise. |
| `devtools` | `boolean` | `true` | The [Convex tab in Nuxt DevTools](/guide/devtools) (dev only). |
| `devScript` | `boolean` | `true` | On the first `nuxt dev` or `nuxt prepare`, rewrite a plain `nuxt dev` script to [`convex dev --start 'nuxt dev'`](/getting-started/installation#run-the-app-and-convex) so one command runs both. A script you have already changed is left alone; `false` never touches `package.json`. |

"Auto-detect" means the package is named in your app's own `package.json` (any dependency field) and resolves. A package that only resolves — hoisted from a sibling app in a monorepo — switches nothing on; set the option to `true` to use one a layer or the workspace root provides.

## Runtime config

The module writes five keys into `runtimeConfig` at build time. Each one is also a Nitro runtime override: set the variable when the built app starts — one container image across environments — and it wins over the built-in value.

| Key | Set at build time from | Runtime override |
|---|---|---|
| `runtimeConfig.public.convex.url` | `convex.url`, then `NUXT_PUBLIC_CONVEX_URL`, then `CONVEX_URL` | `NUXT_PUBLIC_CONVEX_URL` |
| `runtimeConfig.public.convex.siteUrl` | `convex.siteUrl`, then `NUXT_PUBLIC_CONVEX_SITE_URL`, then `CONVEX_SITE_URL` | `NUXT_PUBLIC_CONVEX_SITE_URL` |
| `runtimeConfig.public.convex.crossDomainCallbackRoute` | `convex.betterAuth.crossDomainCallbackRoute` | `NUXT_PUBLIC_CONVEX_CROSS_DOMAIN_CALLBACK_ROUTE` |
| `runtimeConfig.public.convex.loginPath` | `convex.betterAuth.loginPath` | `NUXT_PUBLIC_CONVEX_LOGIN_PATH` |
| `runtimeConfig.convex.siteUrl` (private) | same as the public `siteUrl` | `NUXT_CONVEX_SITE_URL` |

Trailing slashes are stripped from both URLs. If no deployment URL is found the module warns at startup and the client is not created; see [troubleshooting](/getting-started/troubleshooting).

## Import aliases

The module registers ordered `#convex/*` aliases (for both Vite and Nitro) pointing at your Convex functions directory and its generated modules, so you never spell out `_generated`:

```ts
import { api } from '#convex/api'
import { query, mutation } from '#convex/server'
import type { Doc, Id } from '#convex/dataModel'
```

| Alias | Resolves to |
|---|---|
| `#convex/api` | `_generated/api` (`api`, `internal`, `components`) |
| `#convex/server` | `_generated/server` (`query`, `mutation`, `action`, …) |
| `#convex/dataModel` | `_generated/dataModel` (`DataModel`, `Doc`, `Id`, …) |
| `#convex/_generated` | `_generated` |
| `#convex` | your functions directory |

::note
Order matters: the specific generated-module aliases are registered **before** the catch-all `#convex`, because the alias resolver is first-match-wins and `#convex` is a prefix of `#convex/api`.
::

The functions directory resolves in order: the `functions` field in `convex.json` (normalized — leading `./` and trailing slashes stripped), otherwise the `convex/` default. If `convex.json` fails to parse, the module warns and falls back to the `convex/` default.

You often don't need `#convex/api` at all: a generated plugin auto-provides the `api` app-wide, so namespace-reading composables and components (`<CheckoutLink>`, …) work with zero arguments.

### `#convex/auth-client`

Beyond `#convex/*`, the module registers one more alias (Vite + Nitro, always — even with Better Auth off, so type-checking resolves): it points at your `betterAuth.authClient` module when set (absolute, or relative to the project root), otherwise at the bundled Better Auth client. The Better Auth runtime (`useBetterAuth`, `<AuthBoundary>` typing, cross-domain helpers) resolves the client through this alias — see [bring your own auth client](/components/better-auth#bring-your-own-auth-client).

### Before codegen runs

`<functionsDir>/_generated/` (`convex/_generated/` by default) does not exist until the first `npx convex dev`. Until then:

- `#convex/api`, `#convex/server` and `#convex/dataModel` resolve to placeholder declarations typed `any` (`Id` stays `string`), so the project type-checks instead of failing on every import.
- The `api`-providing plugin is a no-op, so the features that read a namespace degrade to doing nothing.
- The dev log says `Convex codegen not found in convex/_generated — run npx convex dev`.

The module watches that directory. When codegen lands, the placeholders retire and the plugin picks up the real `api` without a restart — the log says `Convex codegen detected — generated api wired app-wide`.

## Client options

Under Nuxt the module creates the Convex client for you, with no options: both plugins call `new ConvexVueClient(url)`. `ConvexVueClientOptions` — `verbose`, `logger`, `unsavedChangesWarning`, `skipConvexDeploymentUrlCheck` and the rest — can't be set from `nuxt.config`. They are available where you construct the client yourself, in a [plain Vue app](/guide/plain-vue).

## Security (CSP)

[`nuxt-security`](https://nuxt-security.vercel.app) is an optional companion. Install it and the module detects it, registers it as a module dependency (no `modules` entry needed — if you list it yourself, Nuxt dedupes), and tightens a **Convex-aware Content Security Policy** on top of its defaults: in production `connect-src` allows your deployment — and, when `siteUrl` is configured, the `.site` origin — over both HTTPS and WebSocket, while `img-src` / `media-src` allow Convex-served storage from both origins.

```bash
npm i nuxt-security
```

Your own directives are preserved — the Convex origins are appended. Opt out with `convex: { security: false }`; disabling nuxt-security itself (`security: false`) or its CSP (`security.headers.contentSecurityPolicy: false`) skips it as well. Configure everything else through the standard `security` key.

::note
The CSP is one part of a larger picture — the hardened auth proxy, auth tokens in SSR payloads, safe post-sign-in redirects, and a production checklist all live on the [Security](/getting-started/security) page.
::
