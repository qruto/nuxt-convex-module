:readme-hero

`nuxt-convex-module` is the Convex client for Nuxt: live queries, mutations, actions, pagination, file storage and SSR, auto-imported and typed against your deployment. Install it, point it at a deployment, and your pages read and write Convex data reactively.

Underneath is a complete [Vue](https://vuejs.org) client with composables shaped the [VueUse](https://vueuse.org) way. It runs in a [plain-Vue app](/guide/plain-vue) too, with no Nuxt involved.

## What you get

- ⚡ **Live data** — [`useQuery`, `useQueries`](/guide/queries), [`useMutation`, `useAction`](/guide/mutations-and-actions) and cursor [`usePaginatedQuery`](/guide/pagination), over one `ConvexVueClient`.
- 🖥️ **SSR and preloading** — [`fetchQuery`, `preloadQuery` and `useAsyncQuery`](/guide/server-and-ssr) for hydration-safe server rendering.
- 📁 **File storage** — [`useUpload`, `useUploadQueue`, `useStorageUrl`](/guide/file-storage).
- 🔐 **Auth state** — provider-agnostic [`useConvexAuth` / `provideConvexAuth`](/guide/auth-state) and the `<Authenticated>` / `<Unauthenticated>` / `<AuthLoading>` / `<AuthRefreshing>` components.
- 🧩 **Opt-in integrations** — install [Better Auth, Clerk, Auth0 or Polar](/components) and they wire themselves up.
- 🛡️ **Security** — install [`nuxt-security`](/getting-started/security) and the CSP learns your deployment's origins; the auth proxy, SSR payloads and sign-in redirects ship hardened on their own.
- 🧰 **DevTools** — a Convex tab in [Nuxt DevTools](/guide/devtools): connection, live subscriptions, server logs, auth state.

### Only here

Some of that has no counterpart in Convex's React client — it exists because Nuxt makes it possible:

- 📁 **File storage composables** — `useUpload`, `useUploadQueue`, `useStorageUrl`: upload with progress, queue with bounded concurrency, resolve URLs reactively.
- 🖥️ **`useAsyncQuery`** — a Convex query with Nuxt's `useAsyncData` shape: real data in the server-rendered HTML, then live.
- 🔌 **The `api` object, provided app-wide** — namespace-reading composables and components work with zero arguments.
- 🛡️ **Security wiring** — the Convex-aware CSP, the hardened auth proxy, the `auth` route middleware and `resolveAuthRedirect()`.
- 🧰 **The DevTools tab**, and `<AuthRefreshing>` for the token-refresh window.

::callout{icon="i-lucide-blocks"}
Core Convex is always on. Every opt-in package, and how it switches itself on, is in [Components](/components).
::

## Coming from Convex React

The API is the one [Convex's React client](https://docs.convex.dev/client/react) documents. `useQuery`, `useMutation`, `usePaginatedQuery`, `preloadQuery` and `fetchQuery` keep their names, take the same function references and arguments, and resolve to the same values with the same loading and error semantics. A snippet from the Convex docs or a Stack article reads the same here; what changes is Vue's shape, never the Convex part.

`convex/react` and `convex/nextjs` are ported in full, hook for composable, and each integration is ported with its upstream public API. The port is kept diffable against the upstream sources, so it tracks releases file for file. The Convex release it matches:

:upstream-baseline{source="convex"}

### Reactivity, the VueUse way

- Inputs accept `MaybeRefOrGetter` and are read with `toValue`, so args stay reactive.
- Derived results are `ComputedRef`; owned subscription state is a writable `ShallowRef`.
- Where upstream returns an object (`useConvexAuth()`, `usePaginatedQuery()`), the fields are refs, so the documented destructuring stays reactive.
- Positional `useQuery` **throws** on error, like React's render-throw; the `_experimental` object form returns a `{ status }` union.

### Names and wiring

| Upstream | Here | Why |
|---|---|---|
| `convex/react` — `ConvexReactClient` | `ConvexVueClient` | Same constructor, options and methods; `ReactMutation` / `ReactAction` are `VueMutation` / `VueAction`. |
| `convex/react` — `<ConvexProvider client={…}>` | the module's client plugin | Nuxt builds and provides the client from your config; composables reach it with `useConvex()`. In [plain Vue](/guide/plain-vue) you provide it yourself. |
| `<ConvexProviderWithClerk>`, `<ConvexProviderWithAuth0>`, `<ConvexProviderWithAuth>` | [`provideConvexAuthFromClerk()`](/components/clerk), [`provideConvexAuthFromAuth0()`](/components/auth0), [`provideConvexAuth()`](/guide/auth-state) | Auth is wired in `setup` rather than by a wrapper component. The Clerk and Auth0 components still ship as drop-ins; there is no `<ConvexProviderWithAuth>` component. |
| `convex/nextjs` — `NextjsOptions` | `NuxtOptions` | Only the name; [`fetchQuery` / `fetchMutation` / `fetchAction` / `preloadQuery`](/guide/server-and-ssr) keep their signatures. |
| `@convex-dev/better-auth` — `convexBetterAuthNextJs()` | [`convexAuth(event)`](/components/better-auth) (alias `convexBetterAuthNuxt`) | Nitro has no ambient request context like `next/headers`, so the H3 `event` is passed explicitly. |
| `@convex-dev/polar` — `<CheckoutLink polarApi>` | [`polarApi` is optional](/components/polar) | It defaults to the auto-provided `api.billing` namespace. |

Everything else Vue-side is additive — [`useAsyncQuery`](/guide/server-and-ssr#useasyncquery-ssr-data-the-nuxt-way), the [file-storage composables](/guide/file-storage), `<AuthRefreshing>`, the [DevTools panel](/guide/devtools) — and displaces no upstream name. The full list of divergences and what is deliberately not ported is in [`PARITY.md`](https://github.com/qruto/nuxt-convex-module/blob/main/PARITY.md).

## Versioning

The module follows [semantic versioning](https://semver.org): everything you can write against — options, runtime config, aliases, auto-imports, subpath exports, peer floors — changes only in a major, and a deprecation stays for at least one minor first. The full promise is in [`STABILITY.md`](https://github.com/qruto/nuxt-convex-module/blob/main/STABILITY.md); every release is on the [changelog](/changelog).
