`nuxt-convex-module` is the [Nuxt](https://nuxt.com) module for [Convex](https://convex.dev) — live queries, mutations, actions, pagination, file storage and SSR, auto-imported and typed against your deployment, with composables shaped the [VueUse](https://vueuse.org) way.

Underneath it is a complete [Vue](https://vuejs.org) client, and the `/vue` subpaths are self-contained — so the same composables also run in a [plain-Vue app](/guide/plain-vue) with no Nuxt involved.

The public API is the one [Convex's own documentation](https://docs.convex.dev) describes. `useQuery`, `useMutation`, `usePaginatedQuery`, `preloadQuery` and `fetchQuery` keep their upstream names, take the same function references and the same argument objects, and resolve to the same values with the same loading and error semantics. A snippet from the Convex docs, a Stack article or an example repo therefore reads the same here — what changes is Vue's own shape (a `ComputedRef` instead of a plain value, a plugin instead of a provider component), never the Convex part. Nothing is renamed to look more Nuxt-y, and the Vue conveniences that have no upstream counterpart are additive.

## What you get

- **Reactive data** — [`useQuery`, `useQueries`](/guide/queries), [`useMutation`, `useAction`](/guide/mutations-and-actions), and cursor [`usePaginatedQuery`](/guide/pagination), backed by a live `ConvexVueClient`.
- **SSR & preloading** — [`fetchQuery` / `fetchMutation` / `fetchAction` and `preloadQuery` + `usePreloadedQuery`](/guide/server-and-ssr) for hydration-safe server rendering.
- **File storage** — [`useUpload`, `useUploadQueue`, `useStorageUrl`](/guide/file-storage).
- **Provider-agnostic auth state** — [`useConvexAuth` / `provideConvexAuth`](/guide/auth-state) and the `<Authenticated>` / `<Unauthenticated>` / `<AuthLoading>` / `<AuthRefreshing>` components.
- **Opt-in components** — install [Better Auth, Clerk, Auth0, or Polar](/components) and they wire themselves up.

Coverage is complete rather than partial: `convex/react` and `convex/nextjs` are ported **in full**, hook-for-composable, and each supported add-on is ported with its **same public API**.

::callout{icon="i-lucide-blocks"}
Core Convex is always on. Every opt-in package — and how it switches itself on — lives in [Components](/components).
::

## Differences from the React API

Names and arguments carry over; the divergences are the ones Vue and Nuxt force.

### Reactivity, the VueUse way

- Inputs accept `MaybeRefOrGetter` and are read with `toValue`, so args stay reactive.
- Derived results are `ComputedRef`; owned subscription state is a writable `ShallowRef`.
- Where upstream returns an object (`useConvexAuth()`, `usePaginatedQuery()`), the fields are refs, so the documented destructuring idiom stays reactive.
- Positional `useQuery` **throws** on error (caught by an error boundary, mirroring React's render-throw); the `_experimental` object form returns a `{ status }` union.

### Names and wiring

| Upstream | Here | Why |
|---|---|---|
| `convex/react` — `ConvexReactClient` | `ConvexVueClient` | Same constructor, options and methods; `ReactMutation` / `ReactAction` are `VueMutation` / `VueAction` for the same reason. |
| `convex/react` — `<ConvexProvider client={…}>` | the module's client plugin | Nuxt builds and provides the client from your config; composables reach it with `useConvex()`. In [plain Vue](/guide/plain-vue) you provide it yourself. |
| `convex/react-clerk`, `convex/react-auth0`, `convex/react` — `<ConvexProviderWithClerk>`, `<ConvexProviderWithAuth0>`, `<ConvexProviderWithAuth>` | [`provideConvexAuthFromClerk()`](/components/clerk), [`provideConvexAuthFromAuth0()`](/components/auth0), [`provideConvexAuth()`](/guide/auth-state) | Wiring auth is a `setup` call rather than a wrapper component. Components of the same names still ship, for drop-in parity. |
| `convex/nextjs` — `NextjsOptions` | `NuxtOptions` | Only the name; [`fetchQuery` / `fetchMutation` / `fetchAction` / `preloadQuery`](/guide/server-and-ssr) keep their signatures. |
| `@convex-dev/better-auth` — `convexBetterAuthNextJs()` | [`convexAuth(event)`](/components/better-auth) (alias `convexBetterAuthNuxt`) | Nitro has no ambient request context like `next/headers`, so the H3 `event` is passed explicitly. |
| `@convex-dev/polar` — `<CheckoutLink polarApi>` | [`polarApi` is optional](/components/polar) | It defaults to the auto-provided `api.billing` namespace. |

Everything else Vue-side is additive — [`useAsyncQuery`](/guide/server-and-ssr#useasyncquery-ssr-data-the-nuxt-way), the [file-storage composables](/guide/file-storage), `<AuthRefreshing>`, the [DevTools panel](/guide/devtools) — and displaces no upstream name. The exhaustive list of divergences, the pinned upstream versions each area matches, and what is deliberately not ported live in [`PARITY.md`](https://github.com/qruto/nuxt-convex-module/blob/main/PARITY.md).
