Two ready-made apps you can create with `create nuxt`. Both run against a Convex deployment of your own.

## Starter

An unbranded Nuxt app with the module installed and one Convex table: a message list rendered on the server that updates live, and a form that adds to it.

:pm-create{template="gh:qruto/nuxt-convex-module/templates/starter"}

Then start it with the `dev` script, as described in [Run](/getting-started/installation#run). The app's functions are in `convex/messages.ts`, its page is `app/app.vue`, and `convex/_generated` is included so the app type-checks before the first run. [View the source](https://github.com/qruto/nuxt-convex-module/tree/main/templates/starter).

## Example: playground

One page that runs every core feature, one click each, in this site's design: live queries, mutations with optimistic updates, cursor pagination, file storage, actions, and server rendering with `fetchQuery`.

:pm-create{template="gh:qruto/nuxt-convex-module/examples/playground"}

It is also the app behind the **Open in StackBlitz** link on every pull request. [View the source](https://github.com/qruto/nuxt-convex-module/tree/main/examples/playground).

## With pnpm 11 or later

pnpm 11 stops the first install until you decide which dependencies may run build scripts. `create nuxt` 3.x reports that stop as a canceled scaffold, the same as with Nuxt's own starter. The files are already in place, so finish in the new directory:

```bash
cd my-app
pnpm approve-builds
```

`pnpm approve-builds` asks about esbuild, the only package here with a build script, saves your answer to `pnpm-workspace.yaml` and finishes the install. Either answer works. `create nuxt` also skips `git init` after the stop, so run it yourself if you want a repository.
