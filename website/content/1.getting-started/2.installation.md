## Add the module

Install `convex` — the package your functions in `convex/` import from, and a peer of the module — then let `nuxi` add the module:

:::code-group

```bash [pnpm]
pnpm add convex
pnpm dlx nuxi@latest module add nuxt-convex-module
```

```bash [npm]
npm i convex
npx nuxi@latest module add nuxt-convex-module
```

```bash [yarn]
yarn add convex
yarn dlx nuxi@latest module add nuxt-convex-module
```

```bash [bun]
bun add convex
bunx nuxi@latest module add nuxt-convex-module
```

:::

`nuxi` registers the module for you. If you added the package by hand, list it yourself:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-convex-module'],
})
```

That's the whole setup. The composables, components, and server helpers are auto-imported. The module requires **Nuxt >= 4.1.0** and **Node >= 24.11**, and supports `convex` **1.40 and later** — the full list of ranges is on the [stability page](/getting-started/stability#supported-versions). Want security headers? Install [`nuxt-security`](https://nuxt-security.vercel.app) alongside it — the module detects it, registers it for you, and makes its CSP Convex-aware (see [Security](/getting-started/security)).

:::note
Using **strict** pnpm? Set `publicHoistPattern: ['@convex-dev/*']` in `pnpm-workspace.yaml` (`public-hoist-pattern[]=@convex-dev/*` in `.npmrc` on pnpm 9, or `nodeLinker: hoisted`) so Convex can resolve component definitions.
:::

## Configure your deployment

```bash [.env]
NUXT_PUBLIC_CONVEX_URL=https://your-deployment.convex.cloud
NUXT_PUBLIC_CONVEX_SITE_URL=https://your-deployment.convex.site
```

The module reads these variables at build time, so put them in `.env` — the file Nuxt loads automatically. A custom file like `.env.local` only works if you pass it explicitly: `npx nuxi dev --dotenv .env.local`.

`npx convex dev` writes the deployment URL for you, but under the *unprefixed* names `CONVEX_URL` and `CONVEX_SITE_URL`, into `.env.local`. The Convex CLI picks its variable name per framework and falls back to the unprefixed names for Nuxt. The module reads them after the `NUXT_PUBLIC_` names, which means running the CLI is enough on its own — you just have to load the file it wrote (`--dotenv .env.local`). Prefer `NUXT_PUBLIC_CONVEX_URL` for anything you deploy: it is the only one Nuxt will also apply as a runtime override on a built app.

## Run the app and Convex

One command runs both:

:::code-group

```bash [pnpm]
pnpm dev
```

```bash [npm]
npm run dev
```

```bash [yarn]
yarn dev
```

```bash [bun]
bun run dev
```

:::

The first time the module runs it rewrites a plain `nuxt dev` script to `convex dev --start 'nuxt dev'`: the Convex CLI starts the dev deployment, starts Nuxt next to it, and hands it `CONVEX_URL` and `CONVEX_SITE_URL` in the environment — so there is nothing to put in `.env` for local development, and the `--dotenv .env.local` step above is only for running the two on their own. A `dev` script you have already changed is left alone; set [`convex.devScript: false`](/getting-started/configuration#module-options-convex) to keep `package.json` untouched.

Read live data with [`useQuery`](/guide/queries), write with [`useMutation`](/guide/mutations-and-actions), and resolve [`#convex/api`](/getting-started/configuration#import-aliases) from your generated Convex functions.

Until that first `convex dev` has written `_generated/` into your functions directory (`convex/` by default), the `#convex/*` imports are typed `any` and the module's `api`-providing plugin is a no-op; the dev log says so. Nothing to restart — the module picks the generated files up when they appear. Details under [before codegen runs](/getting-started/configuration#before-codegen-runs).

## Add what you need

Auth and billing are opt-in. Install the package and the integration wires itself up — no extra `modules` entries:

:::code-group

```bash [pnpm]
pnpm add @convex-dev/better-auth better-auth   # Better Auth
pnpm add @clerk/vue                            # Clerk
pnpm add @auth0/auth0-vue                      # Auth0
pnpm add @convex-dev/polar @polar-sh/checkout  # Polar billing
```

```bash [npm]
npm i @convex-dev/better-auth better-auth   # Better Auth
npm i @clerk/vue                            # Clerk
npm i @auth0/auth0-vue                      # Auth0
npm i @convex-dev/polar @polar-sh/checkout  # Polar billing
```

```bash [yarn]
yarn add @convex-dev/better-auth better-auth   # Better Auth
yarn add @clerk/vue                            # Clerk
yarn add @auth0/auth0-vue                      # Auth0
yarn add @convex-dev/polar @polar-sh/checkout  # Polar billing
```

```bash [bun]
bun add @convex-dev/better-auth better-auth   # Better Auth
bun add @clerk/vue                            # Clerk
bun add @auth0/auth0-vue                      # Auth0
bun add @convex-dev/polar @polar-sh/checkout  # Polar billing
```

:::

::

Each one is documented in [Components](/components), along with how to force an integration on or off.
