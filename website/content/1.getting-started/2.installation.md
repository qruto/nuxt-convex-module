## Add the module

Add `convex` — the package your functions in `convex/` import from, and a peer of the module — then let `nuxi` install and register the module:

:pm-install{packages="convex"}

:pm-x{command="nuxi@latest module add nuxt-convex-module"}

:::accordion
::::accordion-item{label="Manual setup" icon="i-lucide-wrench"}
If you would rather add the package yourself, install it and list the module:

:pm-install{packages="nuxt-convex-module convex"}

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-convex-module'],
})
```
::::
:::

That is the whole setup: composables, components and server helpers are auto-imported.

:::note
Using **strict** pnpm? Set `publicHoistPattern: ['@convex-dev/*']` in `pnpm-workspace.yaml` (`public-hoist-pattern[]=@convex-dev/*` in `.npmrc` on pnpm 9, or `nodeLinker: hoisted`) so Convex can resolve component definitions.
:::

## Run

One command runs Convex and Nuxt together:

:pm-run{scripts="dev"}

The first time the module runs it rewrites a plain `nuxt dev` script to `convex dev --start "nuxt dev"`: the Convex CLI creates or attaches your dev deployment, writes its `CONVEX_URL` and `CONVEX_SITE_URL` to `.env.local`, and starts Nuxt beside it. The module reads `.env.local` in development, so there is nothing to put in `.env`. A `dev` script you have already changed is left alone; [`convex.devScript: false`](/getting-started/configuration#module-options-convex) keeps `package.json` untouched.

Read live data with [`useQuery`](/guide/queries), write with [`useMutation`](/guide/mutations-and-actions), import your functions from [`#convex/api`](/getting-started/configuration#import-aliases).

Until that first run has written `_generated/` into your functions directory (`convex/` by default), the `#convex/*` imports are typed `any` and the `api`-providing plugin is a no-op; the dev log says so. Nothing to restart — the module picks the generated files up when they appear. Details under [before codegen runs](/getting-started/configuration#before-codegen-runs).

## Point it at the deployment you ship

```dotenv [.env]
NUXT_PUBLIC_CONVEX_URL=https://your-deployment.convex.cloud
NUXT_PUBLIC_CONVEX_SITE_URL=https://your-deployment.convex.site
```

The module reads these at build time from `.env`, the file Nuxt loads on its own, and `NUXT_PUBLIC_CONVEX_URL` is also the runtime override on a built app — one image across environments.

The `.env.local` that `convex dev` writes holds your *dev* deployment, and only `nuxt dev` reads it: a build takes its URL from `convex.url` or these variables. Set in the environment, the `NUXT_PUBLIC_` names win over `.env.local` in development too.

## Optional: add what you need

Auth, billing and security headers are opt-in. Skip this step until you need one; installing the package is the whole wiring — no extra `modules` entries.

**Better Auth** — sessions, sign-in flows, an `/api/auth/**` proxy and the `convex-auth` middleware ([docs](/components/better-auth)):

:pm-install{packages="@convex-dev/better-auth better-auth"}

**Clerk** ([docs](/components/clerk)):

:pm-install{packages="@clerk/vue"}

**Auth0** ([docs](/components/auth0)):

:pm-install{packages="@auth0/auth0-vue"}

**Polar billing** ([docs](/components/polar)):

:pm-install{packages="@convex-dev/polar @polar-sh/checkout"}

**Security headers** — a CSP that knows your deployment's origins ([docs](/getting-started/security)):

:pm-install{packages="nuxt-security"}

How each one switches itself on, and how to force it on or off, is in [Components](/components).

## Requirements

**Nuxt >= 4.1.0** and **Node >= 24.11.0**. The peer ranges below are what you may install; every one but `vue` and `convex` is optional, needed only by the integration it powers. Floors are raised only in a major release.

| Package | Range |
|---|---|
| `vue` | `^3.5.0` |
| `convex` | `^1.40.0` |
| `@convex-dev/better-auth` | `>=0.12.0 <0.13.0` |
| `better-auth` | `~1.6.11` |
| `@convex-dev/polar` | `>=0.9.0 <0.10.0` |
| `@polar-sh/checkout` | `>=0.4.0` |
| `@clerk/vue` | `>=2.0.0` |
| `@auth0/auth0-vue` | `>=2.0.0` |
| `nuxt-security` | `>=2.6.0` |

The exact upstream releases the port is diffed against are narrower and stated per package: [Convex](/getting-started/introduction#coming-from-convex-react), and each [component](/components) page.
