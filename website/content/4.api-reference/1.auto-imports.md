Everything below is auto-imported in pages, components, and composables. `useQuery`, `useQueries`, `useMutation`, `useAction`, `usePaginatedQuery`, `useUpload`, `useUploadQueue`, and `useStorageUrl` also have `useConvex*`-prefixed aliases.

For what runs in Nitro server code instead, see [server auto-imports](/api-reference/server-imports).

## Data

| Name | Description |
|---|---|
| `useQuery` / `useQuery_experimental` | [Reactive live query](/guide/queries) (throwing / result-union). |
| `useQueries` | [A dynamic number of live queries](/guide/queries#usequeries) from one composable call. |
| `useMutation` | [Call a Convex mutation](/guide/mutations-and-actions) (supports optimistic updates). |
| `useAction` | [Call a Convex action](/guide/mutations-and-actions#useaction). |
| `usePaginatedQuery` / `usePaginatedQuery_experimental` | [Cursor pagination](/guide/pagination). |
| `useAsyncQuery` | [SSR-fetched, payload-hydrated live query](/guide/server-and-ssr#useasyncquery-ssr-data-the-nuxt-way) with Nuxt's `{ data, error, status, refresh }` shape. |
| `usePreloadedQuery` | [Hydrate a query preloaded on the server](/guide/server-and-ssr#preloading-for-ssr) with `preloadQuery`. |
| `useConvexConnectionState` | [Live WebSocket connection status](/guide/connection-state). |
| `useConvex` | The underlying `ConvexVueClient`. |

## Auth

| Name | Description |
|---|---|
| `useConvexAuth` / `provideConvexAuth` | [Convex auth state](/guide/auth-state) (provider-agnostic). |
| `<Authenticated>` / `<Unauthenticated>` / `<AuthLoading>` / `<AuthRefreshing>` | [Render by auth state](/guide/auth-state#state-components). |

### With `@convex-dev/better-auth`

| Name | Description |
|---|---|
| `useAuth` | [Better Auth](/components/better-auth) session + actions. |
| `usePreloadedAuthQuery` | Hydrate an SSR-preloaded authenticated query. |
| `<AuthBoundary>` | [Reactive unauth redirect](/components/better-auth#authboundary) (experimental). |

### With `@clerk/vue` / `@auth0/auth0-vue`

| Name | Description |
|---|---|
| `provideConvexAuthFromClerk` / `<ConvexProviderWithClerk>` | [Clerk adapter](/components/clerk) (a port of `convex/react-clerk`). |
| `provideConvexAuthFromAuth0` / `<ConvexProviderWithAuth0>` | [Auth0 adapter](/components/auth0) (a port of `convex/react-auth0`). |

### With `@convex-dev/polar`

| Name | Description |
|---|---|
| `<CheckoutLink>` / `<CustomerPortalLink>` | [Polar checkout & portal links](/components/polar). |

## App API wiring

| Name | Description |
|---|---|
| `provideConvexApi` / `useConvexApi` / `useConvexNamespace` | Provide and consume the [generated `api`](/getting-started/configuration#import-aliases). |

Full signatures live in the generated reference: [client](/api-reference/reference/client) covers the core composables and components, with per-integration modules under [better-auth/client](/api-reference/reference/better-auth/client), [clerk/client](/api-reference/reference/clerk/client), [auth0/client](/api-reference/reference/auth0/client), and [polar/client](/api-reference/reference/polar/client) — see [all modules](/api-reference/reference).
